Mini Zia — Business Insight Generator

An automated KPI analyst. Point it at business data and it answers the question a manager actually asks: “What changed, why, and what should I do about it?” It flags anomalies, compares this period to the last, finds the likely cause, and writes a plain-English summary with recommendations — using a transparent, rule-based engine, not a black box.

01 · The problem

Dashboards show numbers. People need the story.

Every company has dashboards full of KPIs, but someone still has to read them, spot what moved, work out why, and write it up for the weekly review. That's slow, manual, and easy to miss things in. What a manager actually wants is a sentence:

the kind of answer Mini Zia produces
“🟠 Sales dropped 18% in Chennai (Enterprise) vs last week — the likely cause is a 40% fall in leads. Recommendation: increase lead generation and review the regional pipeline.”

Who it's for: founders, ops and revenue leads, and analysts who spend hours turning dashboards into narratives.

04 · How it works

A transparent engine — and why that's a feature

Mini Zia is built from small, single-purpose Python modules: an anomaly detector (statistical outliers), a trend analyzer (period-over-period change and cause/effect between drivers), and an insight engine that turns those findings into natural-language summaries and recommendations.

It's deliberately rule-based and deterministic: the same data always produces the same answer, every number traces back to the data, and there's no risk of a model "hallucinating" a figure. For a tool whose whole job is to be trusted by a decision-maker, that explainability matters more than sophistication.

The optional LLM layer

The codebase includes an optional layer to rephrase the deterministic summary into a more conversational tone via an LLM. It's off by default (and disabled in this public demo) so the core product needs no API keys, has no per-call cost, and sends nothing to a third party — the LLM is polish on top of a solid foundation, not the foundation itself.

05 · Engineering & verification

Built to run, and to keep running

✅ Tested

A pytest suite covers data generation, period extraction, anomaly detection, and the full insight pipeline.

🔁 CI on every push

GitHub Actions runs the tests on Python 3.10, 3.11 and 3.12 — so changes can't silently break it.

🖥️ Runs on any OS

Unicode console output is forced to UTF-8 at startup, so it runs cleanly on Windows, macOS and Linux (no encoding crashes).

📦 Reproducible

Pinned dependencies and a one-command setup; deployed to Streamlit Community Cloud from the repo.

06 · Data & privacy

What happens to your data

The demo runs on synthetic data by default. If you upload a CSV, it's processed in memory to produce the analysis and is not stored — there's no database. Since it's a public demo, use sample or non-sensitive data. In a real deployment, the data-collection layer would read from the client's own governed sources with proper access controls.

07 · Known limitations

What this version is not

  • Synthetic data. The demo's patterns are generated; real value comes from a company's own KPIs.
  • Rule-based, not learning. It applies well-chosen statistical rules; it doesn't learn from history or adapt thresholds automatically (yet).
  • LLM layer disabled. The conversational-rephrasing layer isn't wired to a provider in the demo.
  • Free-tier hosting. The app sleeps when idle and wakes on first visit; fine for a demo, not a production SLA.

09 · Lessons learned

What I'd carry forward

  • Explainable beats clever for decision tools. A deterministic summary a manager can trust is worth more than an opaque model that's occasionally more eloquent.
  • Design the LLM as optional. Keeping the core rule-based means the product works with zero cost and zero data-sharing; the LLM is an upgrade, not a dependency.
  • “Runs everywhere” is real work. A single Unicode print crashed it on Windows — portability needs to be verified, not assumed.
